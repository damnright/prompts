# 产品知识体系

[总导航与资料](README.md) · [产品判断与案例](design.md) · [运营推广知识](../growth-learning/knowledge.md) · [商务商业知识](../business-learning/knowledge.md)

产品知识的中心是：把客户需要的结果，变成能够被理解、购买、使用、交付和持续经营的供给。下面同时讨论商品、数字产品、服务、平台与组织采购；案例用于解释机制，没有练习要求。

<a id="product"></a>
## 1. 产品是什么：从物品、功能到完整价值

产品可以是实体商品、软件、内容、服务、权益或组合。客户通常不为生产过程本身付费，而为某种结果付费。购买空调包含制冷需求，也包含选型、送货、安装、能耗、维修和安全；购买企业系统还包含部署、迁移、培训与持续支持。

常用的价值层次是核心利益、实际产品和附加服务。核心利益回答“为什么需要”，实际产品是规格、功能、质量、品牌和包装，附加服务是交付、安装、保障和支持。层次帮助理解价值从哪里来，不能据此认为附加部分可以随意省去：在一些业务里，安装和售后直接决定产品能否使用。相关分类见[主教材 9.1](https://openstax.org/books/principles-marketing/pages/9-1-products-services-and-experiences)。

| 类型 | 价值怎样产生 | 特别需要理解的条件 |
| --- | --- | --- |
| 实体商品 | 物品的性能、使用体验与可靠性 | 材料、制造、库存、运输、安装、维修、报废 |
| 数字产品 | 软件、信息或在线能力解决任务 | 稳定性、数据、权限、兼容性、持续运行与维护 |
| 服务 | 人员与流程在具体情境中完成结果 | 容量、时段、技能、服务标准、履约波动 |
| 内容与知识产品 | 内容帮助理解、判断、娱乐或学习 | 版权、准确性、更新、适用性、交付与效果的区别 |
| 组合产品 | 多个环节共同完成结果 | 接口、责任归属、配套供给与全程一致性 |
| 平台 | 连接多方，减少搜索、交易和履约摩擦 | 局部供需密度、信任、规则、争议处理与各方收益 |

产品与项目也不同。产品关注可持续供给、客户价值和生命周期；项目是在确定范围内完成一次交付。企业定制系统、装修和设备安装可能同时包含产品与项目，应分别管理可复用能力和一次性承诺。

## 2. 用户、客户与决策链

使用者、付费者、购买者、决策者、审批者、推荐者和受影响者可能是不同的人。家长购买儿童用品，孩子使用；员工使用软件，部门提出需求，采购与财务审核，管理层决定预算。只满足一个角色，交易和实际采用都可能失败。

| 市场关系 | 典型特点 | 产品判断的重点 |
| --- | --- | --- |
| 面向个人（ToC） | 个人或家庭选择，情绪、习惯、信任与价格共同作用 | 理解场景、完整体验、购买门槛和持续价值 |
| 面向企业（ToB） | 多角色决策，重视投入产出、风险、集成与服务 | 同时考虑采购通过、实施可行和员工实际使用 |
| 面向政府与公共机构（ToG） | 受预算、采购程序、验收、资格及公共责任约束 | 按实际项目核对采购和履约要求，不直接套个人购买方式 |
| 渠道与经销 | 最终使用者和直接客户分离 | 消费者价值与渠道库存、利润、周转和服务负担都要成立 |
| 多边平台 | 不同群体相互影响 | 每一方的加入理由、交易机会和规则成本都需要解释 |

“企业客户想提高效率”仍过于宽泛。效率可以指减少返工、缩短等待、降低库存、减少合规风险或提高产能，不同结果会产生不同产品。个人市场也一样，“年轻人喜欢”不能解释购买时机和替代选择。

<a id="market"></a>
## 3. 市场、细分与竞争

市场不只是一个行业标签，而是特定人群在特定情境中的需求和供给关系。有效细分通常结合任务、购买时机、价格承受力、使用频率、决策方式、地域、渠道和服务条件。人口属性可以辅助识别，不能代替需求解释。

国内市场需要看到地区、城乡、生活成本、产业集群、物流半径、季节与语言文化差异，但不能凭“某线城市”“某年龄段”推断每个人的行为。本地家政的可服务市场受人员和交通限制；工业零件市场可能围绕产业集群形成；全国销售的食品仍受保质期与配送条件约束。

| 判断层次 | 含义 | 常见误差 |
| --- | --- | --- |
| 需求存在 | 有人遇到问题，并为解决问题付出代价 | 把兴趣和抱怨直接当成购买需求 |
| 总体市场（TAM） | 按明确边界计算的总体需求空间 | 混用人数、金额、年销售和累计存量 |
| 可服务市场（SAM） | 当前品类、价格、地区、渠道与能力能服务的部分 | 忽略资质、交付半径、产能和采购门槛 |
| 可获得市场（SOM） | 在具体条件下可能争取到的部分 | 用总体规模乘随意比例当销售预测 |
| 现实竞争 | 客户现在怎样解决，包括不解决 | 只比较同类品牌，漏掉替代方式与惯性 |

竞争可以来自另一件商品、人工服务、自建系统、租赁、二手市场或“不购买”。决定是否切换的是增量收益减去价格、学习、迁移、停工、信任和组织阻力等代价。一个更便宜的企业系统，可能因为迁移风险而无法替换旧系统。

市场数据必须说明年份、地域、定义、样本和来源。终端零售额、出厂销售、平台成交额和行业增加值不能直接相加。协会与平台报告可补充视角，其覆盖范围与利益关系也要理解；国内统计口径可查[国家统计局指标解释](https://www.stats.gov.cn/sj/zbjs/)。

<a id="needs"></a>
## 4. 需求、任务与选择原因

需求描述希望改变的处境，功能是实现改变的一种方案。客户要求“导出表格”，可能为了审批、备份或对账；要求“更大包装”，可能为了降低采购次数，也可能为了满足多人共用。直接照做建议，容易解决错问题。

JTBD（Jobs to Be Done）从具体处境中想取得的进展理解选择。功能结果、情绪和社会因素可以同时存在：购买商务服装既要合身耐穿，也可能为了在特定场合表达专业。理论定义与案例见[Christensen Institute](https://www.christenseninstitute.org/theory/jobs-to-be-done/)。

需求强度要结合发生频率、失败后果、紧迫性、当前替代方式、实际付出与决策权。低频但后果严重的需求仍可能很强，如设备检修和安全保障；高频但几乎无代价的烦恼未必能支撑付费。

购买还受到“推动”和“阻力”共同影响。旧办法的不满、新方案的吸引力推动改变；习惯、学习成本、损失担忧和不信任阻碍改变。因此解释效果、试用、迁移支持和售后保障可能比增加功能更有用。

明确承诺与潜在需求应区分。顾客没有提到防火、食品安全、个人信息保护，不表示这些可以舍弃；它们可能是交易的基本前提。需求判断不能覆盖法定责任。

<a id="research"></a>
## 5. 研究方法、证据与偏差

研究的价值在于减少影响决策的不确定性。不同方法回答不同问题，不能把一类证据扩大成另一类结论。

| 方法 | 较适合回答 | 主要限制 |
| --- | --- | --- |
| 公开资料与行业数据 | 规模、产业链、规则、供给与趋势 | 数据可能滞后，分类未必对应目标细分 |
| 访谈 | 真实经历、选择原因、流程与顾虑 | 回忆、礼貌与表达偏差；不能估计所有人的比例 |
| 现场观察与情境研究 | 实际动作、环境、等待与变通办法 | 被观察者可能改变行为，场景覆盖有限 |
| 问卷 | 已明确问题的分布与群体差异 | 样本招募和题目设计会影响结果；意愿不等于付款 |
| 销售、客服、售后材料 | 购买阻力、故障、退货与交付问题 | 只覆盖已接触者，投诉者不代表所有客户 |
| 使用与交易数据 | 实际采用、漏斗、重复购买和质量表现 | 记录可能不完整；相关性不直接证明原因 |
| 样品、原型与对照实验 | 理解、体验、特定改变的影响 | 试验环境与真实交付不同，小样本结果不稳定 |

访谈对象随研究问题选择。购买判断可能需要付费者、采购者与未成交者；使用问题可能需要实际使用者，包括顺利使用、遇到困难或已经退出的人；平台还可能需要供需双方。企业负责人能够解释预算，不一定知道员工怎样操作。选择不同角色和经历，是为了发现差异，不表示访谈样本已经代表整个市场。

提问以一次具体经历为起点，例如“最近一次预约维修时，事情从发现故障到处理结束是怎样发生的？”再了解当时的环境、顺序、替代办法、决定者、实际花费和放弃原因。受访者笼统地说“预约很麻烦”，与描述一次等待审批后错过时段的经历，能够支持的判断不同。询问“如果有某功能会不会购买”更容易得到设想和礼貌回应，不能代替实际选择；具体回忆同样可能出错，需要与获准查看的记录或观察相互核对。

单次访谈先保留角色、情境、行为顺序和信息来源，把受访者的陈述与研究者的解释分开；一条建议可以对应多个原因。跨次综合再比较相近情境下的共同问题与差异，并保留不符合原解释的案例，避免为了统一结论删掉例外。多次提到某问题说明它值得进一步理解，不直接证明发生比例或解决方案有效；范围和因果判断还需结合交易、使用、交付或其他证据。方法阅读见[Product Talk 访谈指南](https://www.producttalk.org/customer-interviews/)，指定范围见[资料导航](README.md#32-专题资料需求决策与体验)，完整判断示例见[预约维修案例](design.md#research-case)。

事实、解释和假设应分开。事实是“这一批退货中尺码不合适占某比例”；解释是“尺码表达影响购买”；假设是“改尺码说明会减少退货”。原因可能还包括版型、质检和渠道客群，不能仅凭一种解释做全部决策。

常见偏差包括只听现有客户、把熟人当目标市场、只看成功案例、提问暗示、忽略失访和未成交、按结果倒推原因。样本数量大不自动消除招募偏差；不同渠道来的人也不能不加区分地合并。

研究结论的强度应匹配证据：可以说发现某类问题，不能因此宣布全国存在同样比例的需求。AI 模拟用户只反映模型生成的可能性，不能替代观察、交易或用户经历。

<a id="strategy"></a>
## 6. 产品战略、定位与差异化

愿景说明希望创造的长期价值；战略说明选择服务谁、以什么方式取胜、依靠哪些能力，以及放弃什么；目标说明希望改变的结果；路线图表达方向和顺序；任务列表安排具体工作。把五者混在一起，会使“战略”变成不断加功能。

定位需要同时说明客户、情境、价值、参照对象和可信理由。差异化只有被客户理解并在实际交付中兑现，才可能影响选择。“功能多”“使用 AI”“高端”“便宜”都只是属性，必须连接具体收益。

| 差异方向 | 可能带来的价值 | 相应代价或成立条件 |
| --- | --- | --- |
| 性能与功能 | 更快、更准确、更耐用或完成更多任务 | 技术、生产与验证成本；客户是否需要该性能 |
| 可靠性与安全 | 降低故障、损失和不确定性 | 标准、测试、供应与维护投入 |
| 便利性 | 减少时间、步骤、搬运与学习 | 物流、服务覆盖、集成与容量 |
| 服务 | 安装、培训、响应和解决问题 | 人员技能、服务成本、排班与一致性 |
| 品牌与信任 | 降低购买风险，提供身份与情绪价值 | 长期一致性和可信证据，不能只依赖传播 |
| 聚焦细分 | 更贴合特定场景和客户流程 | 市场范围较小，过度定制可能削弱复用 |

[SVPG 的四类风险](https://www.svpg.com/four-big-risks/)可以帮助拆开判断：客户是否认为值得、能否顺利使用、能否实现、商业条件是否成立。实体商品还要考虑可制造性、供应和售后；服务要考虑可交付容量；平台要考虑多方同时成立。一个条件成立不能替代其他条件。

竞争优势还包括渠道、规模、供应、数据、流程、网络关系和组织能力。它们是否难以复制、能否持续产生客户价值，比“我们比别人早做”更重要。专利、独家供应和监管资格的有效性应按具体事实核对。

<a id="development"></a>
## 7. 创新与产品开发

创新不仅是发明新技术，也可以是改善性能、重组供给、降低交付成本、改变购买方式、服务新场景或建立新组合。新颖不直接等于有价值，价值也不一定要求技术新颖。

一般开发过程包含问题发现、创意筛选、概念形成、商业分析、开发、测试、试产或试运行、推广与复盘。阶段用来减少不同风险，可以反复返回；不能把流程齐全当作市场一定接受。阶段原理见[主教材 10.2](https://openstax.org/books/principles-marketing/pages/10-2-stages-of-the-new-product-development-process)。

| 证据形式 | 能帮助判断 | 仍不能证明 |
| --- | --- | --- |
| 概念描述 | 是否理解、是否与某个问题有关 | 真实使用和交付可靠性 |
| 交互或外观原型 | 任务理解、操作、形态和部分体验 | 量产质量、长期效果和全部性能 |
| 技术样机 | 特定条件下能否实现 | 批量制造、成本和全场景可靠性 |
| 试产、试运行 | 生产或服务流程、缺陷和容量 | 全国推广后同样表现 |
| 实际购买与使用 | 购买、交付和采用行为 | 持续复购、长期利润与所有人群的需求 |

MVP（最小可行产品）是足以围绕关键假设获得可信学习的最小产品或交付形式，重点是减少不必要投入并了解实际选择与行为，形式可以是简化版本或人工交付。概念见 [Lean Startup 官方方法](https://theleanstartup.com/principles)。研究原型与真正对外交付的要求不同；一旦交付商品或服务，可以缩小规格和功能范围，但不能省去适用的安全、必要售后或履约条件。生产模具、库存、医疗与高风险服务的试错方式，也不能照搬可随时更新的软件。

规模化之前要理解重复交付的条件：质量是否稳定、采购能否跟上、服务是否可复制、成本是否随量变化、支持是否堆积。一次成功销售只说明一次交易发生。

<a id="portfolio"></a>
## 8. 优先级与资源取舍

优先级比较的是资源用于不同选择的收益与代价。客户影响、证据强度、投入、风险、依赖、时机和机会成本都应考虑。大客户提出的需求不自动最重要，但合同承诺和集中度风险确实会改变判断。

| 方法 | 主要用途 | 使用边界 |
| --- | --- | --- |
| Kano | 区分基本期待、性能收益和惊喜因素 | 分类随人群和时间变化；不能据此删除安全要求 |
| MoSCoW | 区分必须、应有、可有与本轮不做 | “必须”应有明确理由，否则退化成全部最高优先级 |
| RICE | 比较覆盖、影响、信心和投入 | 口径需要一致，猜测数字不能制造客观性 |
| 成本与延迟代价 | 看等待造成的损失及实施负担 | 不确定收益、不可逆投入和相互依赖需单独说明 |

能快速完成不表示值得完成；投入很多也不表示值得继续。已花掉且无法收回的成本不能单独支持后续投入，具体经济原理见[商业经济学](../business-learning/knowledge.md#economics)。

需求有依赖时，逐项评分可能产生错误顺序。新设备需要配套耗材和服务；新交易方式需要客服和对账；只优先做前端宣传，可能造成后台无法兑现承诺。

## 9. 产品组合、产品线与 SKU

品类是一组满足相近需求的供给，产品线是企业提供的相关产品，单品是具体产品项目，SKU 通常用于区分可独立管理的销售或库存单位。服装款式再按颜色和尺码形成多个 SKU；不同企业对 SPU、型号和内部编码的定义可能不同，使用前要统一口径。

组合宽度关注有多少产品线，深度关注某一产品的规格与变化，长度关注项目总数，一致性关注产品之间的联系。概念见[主教材 9.2](https://openstax.org/books/principles-marketing/pages/9-2-product-items-product-lines-and-product-mixes)。

SKU 扩展可以覆盖更多偏好，也会增加采购、备货、仓位、预测、缺货、滞销、退换和质检负担。软件的版本、套餐和兼容范围，服务的项目、时段和人员等级，同样可能产生组合复杂度，只是不用库存件数来表示。

产品之间还会互相替代或促进。新套餐可能吸引新客户，也可能让原有高价客户降档；配件能增加主产品价值，但缺货会拖累主产品。判断组合时应同时看总收益、客户选择与履约复杂度。

引流款、利润款、形象款、配套款是经营角色，不是永久标签。低价引流必须有合理的后续交易与服务成本；不能只看某单品销量就宣布组合成功。BOM（物料清单）则说明产品由哪些材料和部件组成，与销售 SKU 相关但用途不同。

<a id="experience"></a>
## 10. 完整体验、包装与服务蓝图

客户旅程可以包括发现、比较、购买、付款、配送、安装、使用、维修、再次购买和退出。线上页面只是其中一段；实体店、客服、物流和合作方也会改变对产品的判断。

服务蓝图把客户可见动作、前台服务、后台流程和支持资源连接起来。例如预约成功的页面背后，需要人员排班、地址确认、工具、交通和取消处理。只优化前台流程，可能把等待和错误转移给后台。

| 体验原则 | 数字与实体业务中的含义 |
| --- | --- |
| 易理解 | 名称、规格、价格、适用条件和下一步清楚，减少误购 |
| 有反馈 | 用户知道订单、设备、请求或服务当前处于什么状态 |
| 可恢复 | 能纠错、取消、退换、重试或获得人工帮助，适用条件明确 |
| 贴合情境 | 考虑噪声、光线、网络、手套、移动、年龄与能力差异 |
| 可及性 | 关键操作、信息和服务能被不同能力的人理解与使用 |
| 一致性 | 销售介绍、包装、合同、产品和售后表达相互一致 |

包装承担保护、运输、保存、识别、信息表达、开启和处置等功能，不只是视觉设计。标签影响客户能否理解容量、成分、使用方法、限制与责任。功能解释见[主教材 9.7](https://openstax.org/books/principles-marketing/pages/9-7-creating-value-through-packaging-and-labeling)；国内标签和包装要求按实际类别查[国家标准](https://openstd.samr.gov.cn/bzgk/std/)及对应监管规定。

体验优化应关注完整结果，而不是单独减少步骤。提前展示限制可能降低短期购买率，却减少后续退款和争议；必要的确认也可能降低误操作。

## 11. 需求表达、规格、验收与变更

清楚的产品定义包含服务对象、使用情境、价值、规格、适用与不适用条件、交付范围、质量要求和责任边界。软件 PRD、工业规格书、服务项目说明和采购技术要求的形式不同，作用都是让各方对供给达成一致。

功能说明“能做什么”，质量说明“在什么条件下做到什么程度”。“响应快”“质量好”“全天服务”太含糊，需要理解对应的负载、环境、样本、时间和范围。指标越精确，越应确认实际测量和交付能力。

验收确认约定的结果是否交付，不自动证明客户经营目标已实现。企业系统通过上线验收，不表示员工已经采用；培训完成课时，不表示保证某个成绩。销售表达必须与这种区别一致。

标准化提升复用和一致性，定制提高场景适配，但增加设计、生产、支持和维护负担。是否定制要考虑额外收入、后续复用、版本分裂和其他客户的机会成本，不能只看一次报价。

变更可能改变材料、供应、交期、库存、接口、价格和合同责任。软件更新比较容易回退，也可能影响数据和用户习惯；已生产的商品和已售服务权益则无法靠发布新版本消除旧承诺。

<a id="quality"></a>
## 12. 质量、安全、制造与供应

质量至少包含符合规格、适用性、可靠性和交付一致性。安全与适用法规是底线，顾客满意度不能替代这些要求。质量成本不仅是检查投入，还包括预防、返工、报废、退换、保修、事故与信誉损失。

| 类型 | 常见质量条件 | 扩张时容易暴露的问题 |
| --- | --- | --- |
| 商品与设备 | 材料、工艺、批次、尺寸、寿命、环境与运输 | 良率下降、供应替代、批次差异、维修能力不足 |
| 数字产品 | 正确性、稳定性、兼容性、数据与权限 | 高并发、更新破坏、依赖变化、支持积压 |
| 服务 | 技能、流程、及时性、环境和沟通 | 人员差异、排班紧张、等待增加和培训不足 |
| 组合产品 | 单部分质量与接口协同 | 主体互相推责、缺少配套、交付交接失误 |

实体产品开发需要理解可制造性与可装配性。样机可能由高手手工完成，量产必须在可控流程和成本下重复实现。材料、模具、工艺公差、检测、包装、备件和维修方案都会影响总成本。

供应商变化不是纯采购问题。更换材料或部件可能改变性能、安全、认证、包装和售后；单一供应、最低起订量、长交期也会限制产品策略。采购单价较低不代表总成本低。

故障与投诉应区分偶发、批次、设计、环境和使用误解。补偿能够处理单次体验，不能替代根因修正。召回、保修、产品责任和信息披露的适用要求见[国内法律知识](../business-learning/knowledge.md#law)。

## 13. 服务容量、内容与智能产品

服务产能往往与人员、地点和时间绑定。空着的预约时段过后无法储存，超卖时段又会造成等待与质量下降。因此获客、排班、预约、取消、迟到、峰谷和服务标准必须一起理解。

预付款改善当期现金，却形成未来交付义务。收款不意味着服务已经完成，不能把全部现金自由用于扩张。财务和预付责任分别见[财务](../business-learning/knowledge.md#finance)与[法律](../business-learning/knowledge.md#law)。

服务质量差距可能发生在顾客期待与内部理解、内部理解与标准、标准与实际执行、实际执行与传播承诺之间。仅培训员工或提高广告承诺，未必解决真正的差距；原理见[服务质量差距模型](https://openstax.org/books/principles-marketing/pages/11-3-the-gap-model-of-service-quality)。

内容产品应考虑准确性、完整性、适用人群、版权、更新和表达。娱乐、教育、咨询、医疗信息的质量要求不同；交付内容不等于保证使用结果。推荐和生成内容还会受到数据、反馈与审核机制影响。

AI 产品的流畅表达不保证事实正确。可靠性、错误后果、响应时间、成本、个人信息、内容来源、人工介入与使用者能否识别限制都会影响价值。具体技术和监管要随实际用途核对，不把所有智能产品都视为同一类业务。

<a id="commercial"></a>
## 14. 商业模式与产品结构

商业模式说明价值给谁、由谁付费、怎样获得收入、怎样交付以及依靠哪些资源和合作。产品结构与收费单位需要配合：按件、按次、按期、按使用量、按席位、按项目或按结果，对风险分配和使用行为的影响不同。

一次收费而长期服务，会形成持续负担；按量收费可以贴近成本，也可能让客户难以预测预算；会员可以改善重复交易，但权益过多会提高服务成本。具体机制见[商业模式](../business-learning/knowledge.md#models)和[定价](../business-learning/knowledge.md#pricing)。

免费、低价、补贴和试用都是成本由某一方承担的交易安排。应理解限制、转化、使用负担、退出与实际价值；不能把免费用户视为没有交付成本。

价值链包括研发、供应、生产、流通、销售、服务和回收等环节。自营或外包改变能力和控制方式，但不必然解除对客户的责任。关键环节是否可靠、合作方收益是否成立，都会影响产品是否能持续供应。

## 15. 产品与渠道适配

渠道决定谁看到产品、怎样理解、怎样比较、怎样交易和获得服务。产品适合一个渠道，不表示适合所有渠道。

| 渠道情境 | 对产品的主要要求 |
| --- | --- |
| 线下货架与门店 | 包装识别、空间效率、演示、导购、陈列、补货和售后 |
| 电商搜索与详情页 | 可比较规格、图片说明、评价、物流、退换和信任 |
| 内容、短视频与直播 | 价值能被解释或演示，传播承诺与实际效果一致 |
| 企业直销与经销 | 场景方案、报价、证明材料、实施、培训与回款 |
| 本地生活 | 服务半径、可预约时段、地点、到店与人员质量 |
| 平台撮合 | 供需信息、匹配、履约、纠纷与多方信任 |

不同渠道使用不同规格或套餐，可以适配成本和场景，也可能造成误解、渠道冲突和售后混乱。比较条件、权益、服务主体与价格差异需要清楚。渠道策略与国内具体平台见[运营推广](../growth-learning/knowledge.md)。

<a id="measurement"></a>
## 16. 指标、结果与误读

指标用来描述结果和过程，不能代替目标。销量、点击、活跃、成交额、利润、准时交付和故障率分别回答不同问题。产品表现至少需要同时理解客户价值、采用行为、质量交付和经营结果。

| 维度 | 可观察的例子 | 容易误读的地方 |
| --- | --- | --- |
| 客户结果 | 任务完成、问题减少、可靠使用、满意与推荐 | 满意度和自报效果不自动证明客观改善 |
| 采用行为 | 激活、持续使用、复购、续约、使用覆盖 | 频率应符合自然需求；低频不自动代表失败 |
| 质量交付 | 缺陷、退换、故障、投诉、等待、准时率 | 平均值可能掩盖批次、地域和高风险群体 |
| 商业结果 | 收入、贡献、回款、库存与服务成本 | 销量和成交额不是利润，利润不是现金 |

每个指标都要理解对象、分母、期间、事件、排除条件和数据来源。订单创建、支付、发货、签收与退款后的净销售不同；注册、开始使用与完成核心任务也不同。

“北极星指标”是帮助聚焦核心价值的一种方法，不是所有企业必须使用的单一数字。即使选一个主指标，也需要质量、安全、投诉、利润和现金等护栏，避免为了增加主指标而损害整体业务。

分析时应区分渠道、人群、批次、地区和购买时间。整体增长可能只是新增高成本流量；平均退货率改善可能只是商品组合变化。产品实验与归因原理见[运营数据知识](../growth-learning/knowledge.md)。财务口径见[单位经济性](../business-learning/knowledge.md#unit-economics)。

## 17. 采用、产品市场匹配与生命周期

新产品采用通常涉及认知、兴趣、评估、尝试与使用，阶段可能跳跃、反复或终止。降低理解、试用、学习与切换负担，有时比提高曝光更有效；概念见[主教材 10.5](https://openstax.org/books/principles-marketing/pages/10-5-stages-in-the-consumer-adoption-process-for-new-products)。

产品市场匹配（PMF）可以理解为产品在明确市场中持续解决值得购买的问题。判断要结合重复需求、主动采用、付费、替代关系、服务负担和经济性。一个爆款、少数大客户或一次投放成功不能单独证明持续匹配；市场与渠道变化后也可能失去匹配。

复购、续约和留存应符合产品类型。洗护用品有补货周期，耐用品可能长期不再购买但持续可靠使用，企业项目需要看验收、采用、后续维护和再次采购。把日活作为所有产品的成功标准，会诱导不必要的使用。

生命周期中的引入、成长、成熟和衰退可以帮助分析竞争、采用与资源变化，但不是固定时间表。产品可能重新定位、出现新用途、被替代或长期处于小众市场；原理见[主教材 9.3](https://openstax.org/books/principles-marketing/pages/9-3-the-product-life-cycle)。

退出需要处理库存、配件、保修、预付权益、合同、客户迁移和数据等已存在的责任。停止新增销售不意味着旧义务立即结束；维护旧产品也应与新增收益分开判断。

<a id="organization"></a>
## 18. 产品组织、协作与决策

产品职责是把客户、供给、体验与经营约束连接起来，不只是写需求，也不拥有所有专业决定。研发、设计、供应链、生产、销售、运营、财务、法务和客服各有专业责任。

产品负责人关心价值与范围，工程和生产关心实现与质量，销售和运营关心接触与交易，交付和客服关心兑现，财务关心资源和现金。缺少统一承诺时，各部门可能分别优化局部指标，却一起损害客户体验。

决策权、执行责任和知情协作需要明确。谁能改价格、谁能承诺交期、谁批准定制、谁承担质量问题，会影响交易和成本。小团队可以一人承担多种角色，但不能因此省去角色对应的判断。

路线图表达问题、目标和方向，项目计划安排交付依赖与进度，合同承诺则形成外部责任。三者不能互换；具体区别见[NN/g 路线图解释](https://www.nngroup.com/articles/ux-roadmaps/)。

开发方式应匹配风险。软件中小范围可逆更新适合持续迭代；模具、批量库存、工程建设和高风险产品更需要在不可逆投入前设置质量与决策关口。敏捷不意味着没有规格，阶段评审也不意味着不能学习和调整。

## 19. 不同产品类型的重点差异

| 类型 | 产品判断的重点 | 不能直接照搬的做法 |
| --- | --- | --- |
| 日用品与快消品 | 补货、包装、渠道、保质期、规格与品牌 | 用一次销量忽略铺货、退货和临期库存 |
| 耐用品与工业产品 | 使用寿命、可靠性、安装、维修、备件与总拥有成本 | 用短期高频使用判断价值，忽略长期责任 |
| 本地服务 | 半径、时段、人员、流程、信任与复购 | 全国流量增长等同于本地可履约增长 |
| 数字软件与内容 | 核心任务、稳定性、兼容、数据、内容与持续运行 | 认为无实体库存就没有持续成本 |
| 平台与交易服务 | 局部供需、匹配、信任、履约和各方收益 | 用总注册数代替可用交易机会 |
| 企业与机构项目 | 决策链、采购、实施、验收、集成和回款 | 成交等同于采用；个性化需求等同于可复用市场 |
| 受专门监管的产品 | 资格、质量、证据、宣传、交付与持续责任 | 用一般营销或 MVP 原则替代适用行业要求 |

知识可以提供通用判断结构，行业经验提供具体约束。食品、医疗、金融、教育、工业设备等不能共用一份“所有产品的资质清单”；相关责任的基本分类与查证方法见[商业法律知识](../business-learning/knowledge.md#law)。
