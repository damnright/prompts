## S1. 缺失值与控制流

**前置：** 阅读 S1，运行 [Basics.swift](Basics.swift)。

找到 `Word.example` 和 `exampleText`。依次使用 `nil`、空字符串和完整句子，预测显示结果。当前例子只把 nil 显示为“暂无例句”，空字符串仍为空；再考虑产品是否要把纯空白输入归一化。

**预期：** 初始输出包含 `example: 暂无例句`。删掉 `??` 会改变返回类型要求；不要用 `!` 让它“通过”。

**产出：** 解释“未提供”“提供但为空”“内容加载失败”三个状态的区别。结束后恢复初始示例，或把自己的变体保存在练习位置。

## S2. 集合、函数与闭包

**前置：** 阅读 S2，仍使用 Basics.swift。

识读 `filter` 与 `map`；新增一个 B1 词条，核对 A2 筛选结果没有变化。再用 `sorted` 对 term 排序，解释排序返回的新数组与原数组各发生了什么。用 Dictionary 按 ID 查找一个不存在的单词，处理 Optional 结果。

**预期：** 初始 A2 词条输出 `A2 terms: speak, review`。不要将 Set 的遍历顺序当作稳定 UI 顺序。

**产出：** 写一个“输入词条数组与 level，返回固定排序词条数组”的函数，说明输入、输出、空数组和未知 level 的约定。

## S3. 值、引用与状态表达

**前置：** 阅读 S3，对照 Basics.swift 的 Word 与 Counter。

先复制 struct，再修改副本；接着复制 class 引用，再修改对象。初始输出应分别是 `value copy: speak / review` 和 `shared reference: 1 / 1`。画出两个变量与数据的关系。

把“加载中、成功、失败”三个布尔值改成一个 enum，给成功状态携带词条列表，给失败状态携带错误说明。判断“正在加载且已失败且未开始”这种非法组合是否还可构造。

再定义一次作答的值类型，包含单词 ID、用户回答与可空评分；说明“尚未评分”为什么不能直接写成 0 分。把 S4 的分数校验接到构造或更新入口，区分数据表示与规则验证。

**产出：** 说明值类型内部若持有 class 引用，复制外层值并不意味着深复制所有对象；能指出何时需要共享身份，何时普通值更简单。

## S4. 校验、错误与生命周期

**前置：** 阅读 S4，观察 Basics.swift 的 `validateScore`。

将输入改为 0、100、-1、101，分别核对合法边界与错误。初始例子对 101 输出 `error: invalidScore`。比较 `try?` 与 do-catch：丢掉错误原因是否会让页面无法区分“缺少分数”和“分数非法”？

在独立的小 class 中加 `deinit` 日志，让对象保存一个捕获自身的闭包。画出引用环，按教材的捕获列表示例改为适当的弱引用，再观察解除最后一个外部引用时的释放。不要把所有闭包一律改成 weak，也不要用 unowned 掩盖未知生命周期。

**验收：** 能解释 `defer` 的执行作用域、错误如何向调用方传播、为什么错误被捕获不代表业务已经恢复。结束后移除临时日志和自己创建的循环引用变体。

## S5. 异步、取消与隔离

**前置：** 阅读 S5，按环境页编译运行 [Concurrency.swift](Concurrency.swift)。

1. 观察正常任务输出 `loaded: 2`。
2. 观察取消任务输出 `cancelled`，而非展示普通错误；取消在创建任务后立即发出，不依赖“刚好等了多久”。
3. 找到 `@MainActor` 状态、`await` 和 `Task.checkCancellation()`；说明数据跨隔离边界时为何使用 Sendable 值。
4. 将加载逻辑换成先返回旧查询、后返回新查询的模拟场景，设计“当前查询标识仍匹配才更新”的保护。取消旧任务和拒收旧结果各解决什么？

**预期：** 原始例子没有真实 HTTP 请求；它能证明取消和隔离用法，不证明网络请求已撤销或数据库回滚。

**设计判断：** 评审“只要放进 Task 就一定后台运行”“actor 内先检查再 await 再修改永远不会竞争”“捕获取消错误后继续发布结果”三句话，逐一说明反例。
