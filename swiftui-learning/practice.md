# SwiftUI 实操：同一个单词流程

[章节导读](README.md) · [状态与任务设计](design.md)

复用[共用环境](../swift-learning/environment.md)中的 App。每单元从上一个可运行版本开始；可以让 AI 生成小块代码，但需要检查改动并运行下面的失败场景。本文描述待完成的练习，不声称仓库已经包含可运行的 iOS App。

统一模型先用 `id、term、level、example`；id 稳定，example 可空。模拟词条使用 `speak / A2 / nil` 与 `review / A2 / Review a word.`，再补一个长词条和长例句用于布局测试。每次运行恢复固定模拟数据，便于比较。

<a id="u1"></a>

## U1. 组合一个能运行的页面

**前置：** 阅读 U1，能在模拟器运行默认 App。

做单词行与详情两种视图：展示词、level 和例句；行本身通过参数接收内容，不在 `body` 内建网络请求或随机数据。只在重复或职责明确时拆子视图，不预建复杂组件库。

**预期：** 修改传入数据后界面随之变化；长例句能换行。用断点或临时日志观察多次 body 求值，说明为什么 body 不适合累计学习次数。

**验收与清理：** 模拟器实际运行，能说明数据如何传到子视图；移除观察用日志，保留页面供下一单元使用。

<a id="u2"></a>

## U2. 一份来源，两个编辑动作

**前置：** 阅读 U2，先看[所有权表](design.md#ownership)。

1. 在合适的父级持有词条集合；使用 iOS 17+ Observation 时，由明确所有者持有 observable 模型，不在每次 body 求值时重新创建它。
2. 编辑页初始复制一个草稿；“保存”校验后按 ID 更新来源，“取消”关闭并丢弃草稿。
3. 分别试空 term、纯空白 term、合法 term；错误时保留草稿与可修正输入。
4. 用 Binding 时说明它会直接修改谁；不要把绑定到来源的输入框称为“取消后完全撤销”，除非确实有回滚设计。

**预期：** 保存后列表与详情一致；取消不改变原词。输入的局部错误不会使整个页面消失。

**验收与清理：** 给每份状态写出所有者、读者、修改入口和结束时机；恢复被编辑的模拟值，继续复用实现。

<a id="u3"></a>

## U3. 列表、导航与稳定身份

**前置：** 阅读 U3。

用 List 展示词条，用 NavigationStack 进入详情；用 Sheet 呈现包含 Form / TextField 的编辑页，并提供错误 Alert / 提示。用词条的稳定 ID 识别行，不以数组下标或每次新生成的 UUID 作为长期身份。

尝试：进入第二行详情 → 返回 → 排序 → 再打开同一词 → 编辑 → 返回；接着过滤到空列表并恢复。解释筛选条件、导航选择和词条数据是否属于同一种状态。

**预期：** 不会编辑到另一行，不会出现旧详情与新列表互相矛盾；空列表说明没有匹配结果并提供清除筛选动作。

**验收与清理：** 保存一次完整操作记录和实际结果即可，不按点击次数打卡；把筛选恢复为默认值。

<a id="u4"></a>

## U4. 加载、失败、取消与过期结果

**前置：** 阅读 U4 和 Swift S5。此时用可控的异步模拟函数，不依赖 Go。

把加载过程建模为互斥状态，模拟成功、空列表、错误和延迟。先定义行为，再写界面：

| 输入条件 | 应显示 / 发生什么 |
| --- | --- |
| 首次加载尚未结束 | 有加载反馈，不把旧的空数组误当作“暂无单词” |
| 返回空列表 | 空状态与下一步动作 |
| 返回错误 | 保留可理解错误和重试入口 |
| 页面离开后取消 | 不向其他页面弹普通失败提示，不再发布已过期结果 |
| 查询 A 慢、查询 B 快 | 最终展示 B；A 晚返回不能覆盖 B |
| 重复进入同一页面 | 按明确的刷新规则加载，不把出现次数当作业务完成次数 |

用 `.task(id:)` 绑定会影响加载的值，比较它与到处启动无持有者 Task 的差异。对于不响应取消的工作，还要在发布时核对当前请求身份。

**验收与清理：** 运行上述变体，说明哪些保证来自任务取消、哪些来自状态核对。移除只用于实验的失败开关，或保留在本地 Preview / 测试配置，避免变成正式用户选项。

<a id="u5"></a>

## U5. 同一任务适配不同空间

**前置：** 阅读 U5，已有列表、详情、编辑。

先用标准布局实现内容优先级：主操作明显、文本可换行、输入可达；宽窗口可以用列表 / 详情组织信息，窄窗口维持清楚的逐级导航。宽窄切换时保留当前词和合理返回位置，不仅放大手机页面。

| 场景 | 必查行为 |
| --- | --- |
| iPhone 竖屏与横屏 | 内容不被安全区遮挡，长词和按钮不互相挤掉 |
| iPad 大窗口与窄窗口 | 选择与导航连续，栏数变化后仍能完成编辑 |
| 系统大字体 | 内容可读、可滚动，按钮文字不被固定高度裁掉 |
| 键盘显示 | 当前输入和保存动作可达，焦点与关闭键盘方式明确 |

**验收与清理：** 在可运行版本中完成同一任务，标注仍失败的具体状态并修复；恢复自己改变的模拟器字体与方向设置。

<a id="u6"></a>

## U6. 无障碍与用户任务检查

**前置：** 阅读 U6。用 VoiceOver 或 Accessibility Inspector 识别无标签控件，再实际操作核心流程。

检查：图标按钮有名称；阅读顺序可理解；状态不只用颜色表示；文字与背景在深浅色下可辨；关键动作不依赖 Hover、复杂手势或很小的点击区域。开启大字体后再次编辑，检查错误提示能被找到。

让目标用户尝试“找到一个词，修改例句，确认保存”，先观察而不代替操作。记录卡点、用户的实际行为与修订理由，连接[产品原型验证 P2](../product-learning/practice.md#p2)；没有参与者时先做自测并标为自测，不能写成已验证用户需求。

**验收与清理：** 对照状态矩阵逐项检查，有实际运行记录；截图只作为补充。停止测试 App，恢复自己调整的辅助功能设置。完成后进入 [Go](../go-learning/README.md)，随后把模拟列表换成真实 API。
