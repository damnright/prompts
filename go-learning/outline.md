# Go 后端开发与服务运行：对话式学习大纲

[Go 学习入口](README.md) · [环境操作](environment.md) · [现有实操](practice.md) · [设计与评审](design.md)

## 1. 学习目标与范围

以 Go 后端开发为主，兼顾服务器基础、基础设施、运维和架构设计，理解语言特性如何影响程序行为。目标是能够理解业务需求、设计接口和数据、实现服务、部署维护，并根据实际问题判断何时需要调整架构。

本大纲用于逐章开展中文对话式学习，共 **7 个阶段、36 章**。章节是知识边界，每章可以拆成多次对话，不要求一次学完。章节编号独立于 `tech-list.md` 的技术路线编号和现有 G1～G7 实操单元；本大纲覆盖更完整的后端能力，不把全部章节作为开始产品开发的前置条件。

### 1.1 贯穿案例与技术主线

贯穿一个逐步发展的后端服务：先处理资源的增删改查，再加入用户权限、数据库、后台任务，最后部署、观察和扩容。词库可以作为资源示例；库存、订单等案例用于解释并发与一致性，不局限于英语 App。

技术主线采用 **Go 标准库 + PostgreSQL + pgx / pgxpool**，服务器以 Linux 为主要学习环境，复用已有的 OrbStack 和 TablePlus。先形成职责清晰的单体服务，后续依据需求讨论缓存、消息队列和服务拆分。

环境与已有数据库按[环境操作](environment.md)检查和复用，不重复安装，也不为学习重新创建相同用途的数据库容器。

### 1.2 学习深度

| 知识类型 | 学习要求 |
| --- | --- |
| 语言语义、数据一致性、并发、资源生命周期 | 理解机制，能解释正常与失败行为 |
| 接口实现、测试、部署、排错、架构取舍 | 能够应用与评审，用运行结果和反例验证判断 |
| 低频语法、工具参数、底层源码 | 能够识读和查证，不要求背诵 |

## 2. 第一阶段：建立后端系统的整体认识

先知道代码运行在哪里、一次请求经过什么，再进入语法。

| 章节 | 学习内容与关键问题 |
| --- | --- |
| **1. 一次请求如何完成** | 客户端、DNS、HTTPS、反向代理、Go 服务、数据库分别负责什么；请求、数据和错误如何流动；区分业务代码、基础设施和外部依赖。 |
| **2. 程序运行的基本模型** | 程序与进程、线程、内存、文件、端口、连接、环境变量；CPU 运算与等待 I/O 的区别；程序退出后哪些数据还在。 |
| **3. Go 工程与开发闭环** | 源码、包、模块、依赖、编译产物；`go.mod` 与 `go.sum`；运行、构建、格式化、测试、调试；读懂报错并用 Git 检查改动。 |

**阶段目标：** 能解释“代码已经写好”“程序正在运行”“服务可以访问”之间的区别。

## 3. 第二阶段：理解 Go 的语言特性

重点放在代码的真实行为，以及这些行为怎样影响后端正确性。

| 章节 | 学习内容与关键问题 |
| --- | --- |
| **4. 值、类型与数据表示** | 变量、常量、零值、类型转换；整数与浮点数；字符串、字节与 Unicode；时间点、时区和时长；金额与精度问题。 |
| **5. 控制流、函数与作用域** | 条件、循环、多返回值、函数值、闭包；变量作用域与捕获；理解参数传递和执行顺序，识别版本相关行为。 |
| **6. 指针、数组、切片与 map** | Go 的值传递；值复制后哪些数据仍共享；切片长度、容量和追加；map 的查找、修改与 `nil`；谁拥有和修改数据。 |
| **7. 结构体、方法与组合** | 用类型表达业务；值接收者与指针接收者；方法集、嵌入、封装；区分数据结构与业务行为，避免无意义的“大对象”。 |
| **8. 接口与泛型的使用边界** | 隐式实现、接口的动态类型与值、接口中的 `nil`；小接口与依赖替换；泛型的基本使用；什么时候直接用具体类型更清楚。 |
| **9. 错误、清理与 I/O** | `error`、错误包装、`errors.Is/As`、`defer`、`panic/recover`；`io.Reader/Writer`；文件和连接的关闭责任；避免吞错与重复记录。 |
| **10. 用测试验证理解** | 单元测试、表驱动测试、边界与失败案例、测试替身、模糊测试入门；检查行为而非内部写法；调试与静态检查各能发现什么。 |

测试从前面的第一个业务函数就开始，第 10 章再系统整理方法。

**阶段目标：** 理解值复制与共享、接口与 `nil`、错误传播、资源释放。切片扩容倍数等实现细节按版本查证，不作为需要背诵的语言规则。

## 4. 第三阶段：实现一个完整的后端服务

把语言知识连接到接口、业务、数据和权限。

| 章节 | 学习内容与关键问题 |
| --- | --- |
| **11. HTTP 服务与请求处理** | `net/http`、路由、Handler、中间件、请求与响应；方法、Header、状态码；从进程、端口、请求结果判断服务是否正常。 |
| **12. API 契约与输入边界** | 资源与动作、JSON、字段缺失与零值、校验、请求体限制、统一错误、稳定分页、兼容演进；接口怎样减少客户端歧义。 |
| **13. 业务逻辑与代码组织** | HTTP、业务规则、数据访问的职责；按业务组织包、明确依赖方向；初始化与依赖注入；什么时候拆层、抽接口，什么时候保持简单。 |
| **14. 外部调用与请求生命周期** | 调用其他 HTTP 服务；连接复用、响应体关闭、超时和取消；`context` 的传递与边界；区分连接失败、业务失败和结果不确定。 |
| **15. PostgreSQL 与数据访问** | 数据建模、约束、参数化 SQL、查询与写入、`pgxpool`；连接池、Rows、NULL、错误映射；真实数据库集成测试。已有 SQL 知识按需衔接。 |
| **16. 事务与并发写入** | 事务边界、隔离、锁、唯一约束、原子更新；重复提交与幂等入门；为什么“先查再写”可能出错；提交结果不确定时如何判断。 |
| **17. 身份、安全与数据归属** | 认证与授权、会话与令牌、密码存储基础、对象归属和租户隔离；注入、敏感日志、密钥管理；通过越权与非法输入测试检查边界。 |

**阶段目标：** 形成一个有权限边界、能持久化、可测试的本地服务。架构设计从业务规则、依赖方向和事务边界开始，不必等到后面的架构专题。

## 5. 第四阶段：理解并发与服务生命周期

先有请求和数据库这些具体场景，再深入并发，理解它解决的问题。

| 章节 | 学习内容与关键问题 |
| --- | --- |
| **18. Goroutine 与共享状态** | 并发与并行、阻塞与调度的基本模型；goroutine 的创建、结束和泄漏；数据竞争；HTTP 请求同时执行时哪些状态需要保护。 |
| **19. 同步与通信** | Mutex、WaitGroup、channel、select；同步关系与可见性；谁负责关闭通道；什么时候用锁，什么时候用通道；运行 race 检查。 |
| **20. 有边界的并发任务** | 并发上限、等待队列、背压、错误汇总、取消传播；批量任务和并行外部请求；避免无限启动 goroutine 和无限重试。 |
| **21. 服务启动与优雅退出** | 初始化顺序、配置校验、信号、停止接收请求、等待在途任务、关闭连接池；后台任务归属；取消请求与完成清理的区别。 |

**阶段目标：** 能回答谁启动任务、谁等待它、谁取消它、什么时候释放资源。

## 6. 第五阶段：服务器、部署与日常运维

目标是能够维护一个实际运行的服务，先建立单机环境下的完整能力。

| 章节 | 学习内容与关键问题 |
| --- | --- |
| **22. Linux 与服务器资源** | SSH、用户与权限、目录、进程、信号、服务管理、日志；CPU、内存、磁盘、文件描述符；定位进程退出、磁盘满和资源不足。 |
| **23. 网络、入口与 HTTPS** | IP、端口、监听地址、DNS、TCP、TLS、反向代理、防火墙；公网与内网；区分连接拒绝、超时、证书错误和代理错误。 |
| **24. 部署形态与基础设施选择** | 二进制部署、systemd、容器、镜像、网络、数据卷、资源限制、Compose；虚拟机与容器的区别；自建和托管服务的责任、成本与恢复能力。 |
| **25. 构建、发布与数据库迁移** | CI/CD、依赖与版本固定、测试和漏洞检查、配置与密钥注入；数据库迁移、新旧版本兼容、发布验证、回滚与向前修复。 |
| **26. 日志、指标与追踪** | 结构化日志、请求 ID、错误率、延迟分位数、吞吐和资源饱和度；服务目标、告警；通过证据判断问题发生在哪一层。 |
| **27. 数据备份与恢复** | 数据、配置和文件分别如何备份；保留策略、恢复验证；可以接受丢多少数据、停多久；理解复制与备份的不同用途。 |
| **28. 故障排查与应急处理** | 从用户现象逐层排查入口、应用、数据库和外部依赖；慢查询、连接池耗尽、内存增长；先恢复服务、保留证据，再定位根因和复盘。 |

**阶段目标：** 能部署、观察、更新和恢复自己的服务。运维内容参考 [Google SRE](https://sre.google/sre-book/table-of-contents/) 对监控、发布、排障和故障处理的划分，练习规模保持在个人能够维护的范围。

## 7. 第六阶段：可靠性机制与架构演进

每一章都从一个真实问题出发，讨论引入机制的收益、代价和失败方式。

| 章节 | 学习内容与关键问题 |
| --- | --- |
| **29. 超时、重试与故障隔离** | 超时预算、退避与抖动、重试放大、幂等协议、限流、降级、熔断；哪些错误可以重试，怎样避免下游故障拖垮整个服务。 |
| **30. 后台任务与异步消息** | 请求内执行与异步执行的选择；任务持久化、重试、重复消费、顺序、死信；数据库任务表、消息队列、Outbox；进程崩溃后任务怎么办。 |
| **31. 缓存与 Redis** | 本地缓存与共享缓存、TTL、失效、一致性、热点、击穿与雪崩；缓存失败时的行为；如何证明缓存值得引入。 |
| **32. 多实例与高可用基础** | 无状态服务、负载均衡、会话与共享状态、健康检查、滚动发布；数据库连接预算、重复定时任务、单点故障和故障域。 |
| **33. 模块化单体与服务拆分** | 模块边界、数据归属、进程边界、同步与异步协作；一致性和部分失败；拆分的需求证据、通信成本与运维成本。 |

**阶段目标：** 理解消息队列、Redis 和服务拆分的机制与判断依据，完整实施按需求展开。它们不作为完成普通业务服务的前置条件。

## 8. 第七阶段：性能分析与综合架构设计

在已有可运行服务和观测证据后，再深入性能与系统设计。

| 章节 | 学习内容与关键问题 |
| --- | --- |
| **34. Go 运行时与性能诊断** | 栈与堆、逃逸、分配、GC、调度；CPU、内存、goroutine 和锁分析；结合 pprof、trace、benchmark 解释现象，理解优化代价。 |
| **35. 压测与容量规划** | 吞吐、并发、延迟分位数、错误率、排队与饱和；代表性负载、瓶颈定位、连接池和资源预算；容量余量与成本。 |
| **36. 从需求到架构方案** | 明确业务约束、规模、可靠性目标与预算；设计接口、数据模型、模块和部署关系；分析正常路径、失败路径、观测、恢复与演进条件。 |

**阶段目标：** 用证据定位瓶颈，并提出与需求、可靠性目标和预算相符的方案。性能部分以 [Go Diagnostics](https://go.dev/doc/diagnostics) 中官方诊断工具的适用范围为依据，围绕“发现瓶颈 → 解释机制 → 修改 → 重新测量”展开。

## 9. 每章的对话式学习方式

### 9.1 内容组织

每个学习单元按以下顺序展开：

**具体问题 → 直观解释 → 机制 → 最小代码 → 运行结果与失败反例 → 设计取舍。**

例如讲数据库事务，除 `Begin / Commit / Rollback` 外，还要讨论：

- 两次写入为什么需要一起成功？
- 两个请求同时修改同一份数据会怎样？
- 数据提交成功，但客户端没收到响应怎么办？
- 哪些规则由 Go 代码维护，哪些应交给数据库约束？
- 如何验证错误路径，而不只验证正常情况？

每次只讲当前章节的一个可消化单元；允许随时追问、换例子、降低难度、深入原理或跳过已掌握部分。不设学习时长和刷题数量，不要求每次回答测验。小实验用于验证理解，阶段性运行用于验证实现能力。

### 9.2 贯穿全程的要求

- 测试、安全、日志和资源释放贯穿课程，专题章节负责系统整理。
- 已掌握的 SQL、HTTP 内容直接复用，重点学习它们与 Go 服务的连接处。
- 架构判断围绕业务规则、状态归属、失败处理、成本和维护难度。
- 区分 Go 语言规则、标准库行为与运行时实现细节；涉及版本差异时核对 [Go 官方文档](https://go.dev/doc/)，标明适用条件。
- 对话讲解以本大纲组织；外部资料用于核对机制和按需深入，引用时给出具体章节或小节，不要求来回跳转才能读懂正文。
- 示例代码、预期结果与真实运行结果明确区分。构建通过不等于启动成功，测试未运行不等于通过。

### 9.3 按需专题与后续进阶

文件与对象存储、SSE / WebSocket、gRPC 可在业务需要时插入专题。

Kubernetes、服务网格、复杂分布式事务和运行时源码深挖放在后续进阶，不作为本课程主线的前置条件。

## 10. 学习顺序与能力检查

```text
后端系统全貌（1～3）
→ Go 语言特性与验证（4～10）
→ 本地 HTTP / PostgreSQL 服务（11～17）
→ 并发与服务生命周期（18～21）
→ 部署、观测与恢复（22～28）
→ 可靠性与架构演进（29～33）
→ 性能、容量与综合设计（34～36）
```

主线按依赖关系推进；已掌握的内容可以跳过，未出现的复杂需求不强制实施。测试、安全和基本排错随功能一起学习，不因专题章节在后而推迟。

| 阶段完成后 | 应具备的能力 |
| --- | --- |
| 第一阶段 | 能沿一次请求说明客户端、网络入口、Go 进程和数据库的职责。 |
| 第二阶段 | 能读懂常见 Go 代码，解释值、共享、接口、错误和资源行为，并用小测试验证。 |
| 第三阶段 | 能实现并验证一个有权限边界、可持久化的本地 API，解释业务与数据约束。 |
| 第四阶段 | 能识别共享状态风险，控制任务并发、取消、退出与资源释放。 |
| 第五阶段 | 能部署、观察、发布和恢复服务，沿证据排查故障。 |
| 第六阶段 | 能判断重试、异步任务、缓存、多实例和服务拆分的适用条件与代价。 |
| 第七阶段 | 能通过测量定位瓶颈，形成覆盖正常、失败、恢复和演进路径的架构方案。 |
